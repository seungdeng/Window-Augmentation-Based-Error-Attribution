발명 배경 LLM 멀티에이전트 시스템(MAS)의 확산과 신뢰성 문제
 다수의 LLM 에이전트가 역할을 분담·상호작용하며 복잡한 작업을 수행하는 MAS가 의료·금융·SW개발 등에 확산
순차적 상호작용 구조로 인해 한 단계의 오류가 이후 단계의 입력으로 전달·전파되어 전체 작업 실패를 유발
 실패 이후 대응의 현재 수준
 실패 시 대응은 전체 작업 재실행(re-run) 또는 전문가의 수작업 로그 분석 → 시간·비용·API 호출 낭비
오류 원인 귀인(failure attribution) 을 통해 실패  원인  단계·에이전트의 식별 연구가 활발하게 이루어지고 있으나 ,  식별된  오류 지점으로부터 궤적을 수리하여 실패를  성공으로 전환하는 연구 부족 Step 1 Agent A Step 2 Agent B  ✕ Step 3 Agent C Step 4 Agent D Task 실패 결정적 오류(Step 2)가 이후 단계로 전파되어 최종 실패 유발 2

발명 배경 본 발명이 다루는 대상: MAS 실행 로그(궤적)
 MAS의 실행 과정은 각 에이전트의 출력이 step 단위로 기록된 상호작용 로그(궤적, trajectory)로 남음
각 step =  에이전트명 , 해당 에이전트의  출력 결과 본 발명은 원 시스템의 내부 구성(코드·프롬프트·설정)에 접근하지 않고, 이 로그만을 입력으로 동작 실패 궤적(로그)의 구조 예시 Step Agent 출력 내용 (Content) 1 Orchestrator "NYSE 도보 5분 내 무술 도장을 찾아라" — 하위 작업 계획 수립 2 WebSurfer 검색 실행, 후보 결과 목록 반환 3 WebSurfer 관련 없는 링크 클릭, 잘못된 정보 추출  ←  결정적 오류 (Decisive Error) 4 Orchestrator 잘못된 정보를 근거로 다음 지시 생성 5 Assistant 오염된 지시 기반 최종 답변 작성 → Task 실패 → 이 로그에는 각 에이전트의 역할·말투·형식과 작업의 진행 상태가 모두 담겨 있음 → 본 발명: 로그의 역방향 추적으로 오류 지점을 찾고(귀인), 로그로부터 수리 조직을 유도(수리) 3
